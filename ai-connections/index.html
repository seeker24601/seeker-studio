How it works

Your agent does the integration. You never write it again.

Every AI project re-solves the same things: which package, which base URL, which auth header and key variable, how to list models, why each SDK fails differently. AI Connections solves them once.

Paste one line

Into Claude Code, Codex or Cursor, or run npx ai-connections-cli skill once so every session knows.

Your agent reads the instructions

From llms.txt: which mode fits, what to install, the patterns to use, and the rules. Keys go in .env and never in code.

Switch providers with a word

A model is just provider:model. Moving from OpenRouter to Anthropic, or to a local Ollama model, changes one string.

One call, any provider

The same code, whatever the model.

Built on the Vercel AI SDK, so streaming, tools and structured output work as documented. AI Connections adds what the SDK leaves to you.

  • Keys found for you from each provider's usual variable, and a pasted key is matched to its provider.
  • One error type, with the provider's own message and whether a retry could help.
  • Model lists straight from the provider, with prices and inputs where stated.

Keys handled

Safe by default

Built for other people's keys.

Made for apps where users' keys and requests pass through your server.

  • Keys encrypted at rest, never returned by the API, and sent only to the provider they belong to.
  • Endpoints held to the provider. Redirects are refused, and local addresses open only to local model runners.
  • Provider errors redacted before end users see them, since they can echo keys or prompts.
  • Links a provider returns are fetched only if they are public HTTPS.
  • SVG output refused unless you opt in, since it can carry script.
  • Releases built in public CI and published through npm trusted publishing, with no stored tokens.

Status

In real use, and honest about its limits.

Running in real apps

Atelier-1111, a desktop image studio, reaches 12 image providers through AI Connections. A multi-agent game harness runs 27 text providers and local models through it.

Building those two is what shaped it.

What isn't proven yet

Providers are checked against their own documentation and tested against local fixtures, but not every one has been tried with a live account. The first real call to a new provider is the true test, and its error comes back in its own words.

AWS Bedrock, Azure and Vertex need dedicated adapters. Requires Node.js 22 or newer.
